# 分层路由设计与开发计划

状态：v0.7.0 实现与验收基准；2026-10-06。下文的“本地证据与现状”记录 v0.6.0 设计起点，并非当前实现；阶段估算为历史规划。
范围：第一阶段不修改 CPA、不部署服务器。实现成员级按顺序、请求级轮流、手动，以及插件内部嵌套路由组。保留随机／加权兼容。额度智能策略为后续研究门禁，不伪装成已支持。

## 2. 核心分层

父组只选择一个直属成员。成员可以是叶子模型或另一个组。子组不可展开成父组的平级候选；选中后由子组自身策略、冷却和尝试预算整体执行。只对叶子调用 CPA，账号／Key 分配继续由 CPA 原路由处理。

第一阶段父组只按成员顺序、轮换或手动选择，不执行账号比较。用户期望的“按子组会先使用的账号／Key 比较”留在额度阶段，不能以模型顺序替代后宣称完成。

内部使用不可变配置快照和树／DAG，不通过 host 回调执行组合模型名。公共子组可以被多个父组引用，但单次路径不得循环。

## 3. 策略语义

### 按顺序：fallback

按直属成员配置顺序执行；跳过可确定不可用的成员；某子组失败且允许父层回退后再尝试下一直属成员。成员内部供应商调度不变。

### 轮流：round-robin

第一阶段明确命名“按请求轮流”：每次真实进入组的执行推进一次起点；预览、状态读取、保存配置不推进。一次请求回退到第二成员不再次推进同一组。共享子组的计数器按子组名共享；只有实际进入时推进。

工具调用续轮、客户端重试都是新请求；不承诺能识别会话每一轮。会话级策略需以后定义会话 ID、重试去重和并发语义。保持现有全局计数行为与重启归零行为。

### 手动：manual

新增 manual_member，值必须是直属成员名称并完整保留前缀。固定成员直到用户保存改选；失败、冷却或模型被替换都不切换其他直属成员。不是跳过防换模检查。

叶子同模型身份重试仍可按原配置执行；供应商内部也可能换 Key。选择子组时允许子组自己的内部回退。界面必须解释“固定成员 ≠ 固定账号／Key”。若需要绝不重试，可将成员 max_retries 设 0。

手动成员冷却时直接返回明确错误，不使用 when_all_cooling 的兜底来改选成员。未选、成员已删或配置失效时配置保存失败；运行时防御性失败关闭，不随机代选。

### 随机／加权

保留现有名称和配置兼容，也应用直属成员边界；不删除用户已有策略。不纳入新的账号级承诺。

## 4. 配置与验证

示例（提案）：

```yaml
virtual_models:
  - name: smart-glm
    strategy: manual
    manual_member: glm-pool
    max_attempts: 8
    members:
      - model: glm-pool
      - model: fallback/glm-5.3-flash
  - name: glm-pool
    strategy: fallback
    members:
      - model: z.ai/glm-5.3-flash
      - model: cline-pass/glm-5.3-flash
```

- 保持 model 字段引用，先查本配置组名，未匹配则按真实模型 ID 处理。名称大小写不敏感，前缀不折叠。
- 不允许组名与真实模型 ID 冲突而静默抢占；页面至少强提示，保存时有可查询模型清单则校验。宿主清单不可用时明确标记未验证。
- 以 DFS 检查自引用和间接循环；输出完整环路。首版最大嵌套路径 8 个组；最长路径计算不得被共享 DAG 的 visited 标记漏掉。
- 现有仅叶子配置保持不变；新组图错误在保存时拒绝，不能像当前归一化那样偷偷删成员。
- 明确 max_attempts 的统计口径：插件叶子 host 调用次数；不等于 CPA 内部 HTTP 或账号重试次数。

## 5. 执行结构与预算

建议引入 ExecutionContext、GroupExecutor、LeafExecutor：公共上下文保存配置快照、路径、全局预算、已经提交的流状态和观测记录。非流式／流式共享组选择和失败分类逻辑，保留各自叶子运输实现。

- 正数 max_attempts 对其子树生效，每个叶子调用消耗所有祖先的剩余预算，不按深度重复计算请求总次数。
- 0 维持兼容：按当次候选遍历和已有身份重试预算计算，不新增无限循环。共享组不同路径计入不同实际进入次数。
- 已实现请求安全硬上限 64 次插件叶子调用，覆盖祖先均设 0 的极端 DAG；达到后返回 attempt_budget_exhausted。
- 子组尝试耗尽后返回带分类的结果，父层决定是否回退。预算耗尽、取消和流已提交是全局终止，不误当可恢复模型错误。
- 子组不会通过 host 调用 combo 名，避免旁路令牌导致 unresolved model。
- 请求体始终从原始体重写为叶子名；不得多次改写而遗失必要字段。

## 6. 失败、冷却和保护

- 每个真实叶子继续按现有 failure kind 记录冷却，不把一个叶子失败扩散成整个组冷却。
- 子组是否可用根据其策略递归判断：手动只看选中成员；其他组看可尝试成员。不是简单看组名的 cooldown。
- 只有全部成员冷却时才沿用 when_all_cooling；soonest 表示按恢复时间优先尝试，不虚假宣称已经等待恢复。手动例外见上。
- 子组普通 4xx 是否继续内部回退由子组 failover_on_client_error 控制；退出后父组可按父层配置决定跨直属成员回退。两层可能不同，需在诊断说明。
- 手动仍检测实际模型并执行配置的身份重试；耗尽后失败，不切其他直属成员。
- 防护继承采取“只增强”：祖先 guard=true 作用于所有叶子；成员 deny 累积且始终优先；显式 expect 校验不得因另一个层级的宽通配取消。
- 首版对子组引用禁止配置 expect/deny/max_retries 等叶子专用覆盖，避免组名被当成响应模型或整个子树重试。子组必须在自身叶子配置精确映射；错误时保存拒绝并解释。
- 冷却和 guard 具体优先级形成测试矩阵，不能简单把父级 expect 传到所有叶子。

## 7. 流式与并发

已向客户端提交任何数据／响应头后，不再跨成员或跨组重试。全树共享 committed 标志；子组返回 post_commit_error 时父组直接终止。保留现有 32 chunks / 256 KiB 身份探测上限，不把首字等待时间与身份探测混为一谈。

配置更新采用请求起始快照：进行中的请求不切到新手动成员；保存后新请求生效。计数器及预览分离；并发轮换使用原子计数保证分配，无公平完成顺序承诺。计数键按名称保留至引擎重启；同名策略改变保留计数，预览和保存均不推进。

## 8. 页面与诊断

- 策略显示“按顺序／按请求轮流／手动”，保留随机／加权。
- 手动卡片单选和明确当前固定成员；删除选中成员要求重新选择。
- 选择器显示叶子与组类型、排除导致环路的组；禁止项给原因，不只隐藏。
- 嵌套预览为树：显示直属成员、子组策略和叶子冷却；随机／加权／轮换树不预测下一次执行的随机或计数结果，执行时重新排序；不得消耗轮换计数。动态状态明确“预计，执行时重新检查”。
- 日志包括 requested_model、group_path、leaf_model、策略、插件尝试数、回退原因和是否已提交；不记录密钥、凭证 JSON 或提示词。
- 组能力仍默认最小公共能力，递归使用子组已声明能力；缺失信息提示而非宣传大上下文。祖先子树按实际长度过滤尚未实现，禁止默认最大能力。
- 手动改选不会悄悄改对外能力；改选到达不到声明的成员必须警告。参考能力复制与 models.dev 功能保持独立。

## 9. 后续额度三策略研究门禁

不在第一阶段添加不可工作的“智能”按钮。

必须先验证：
1. 从宿主获取某模型真实可执行的全部凭证，含禁用、模型支持、认证范围和可用状态。
2. 是否能无副作用预测供应商将先选的凭证；不能调用会消耗轮换状态的 scheduler 来做预览。
3. 统一额度快照来源、更新周期、过期标记、适用模型、周／5h 窗口及 key 消耗统计；QuotaProvider 可供管理查询不等于有统一读回调。
4. 使用 AuthID 的安全与回退含义；原供应商路由、亲和性和现有 scheduler 是否仍生效。
5. 当前 v7 插件 ABI 与 v8 相关接口兼容实验，未经验证不能贸然升级 SDK。

策略草案待确认：
- 智能：先按可用／已耗尽／未知／冷却分层，再按适用重置时间排序；周窗口存在则采用周窗口，但同时遵守短窗口耗尽约束；仅 5h 时用 5h 重置。Key 与订阅之间优先关系需要明确。
- 最少使用：定义剩余比例或统一可用量，二者不得混用；未知不得按无限额度排序。
- 重置前用完：用户“额度减小时”需确认具体公式；建议 remaining_fraction / max(hours_to_reset, 1/60)，明确这不是用户原式。多窗口取可用瓶颈；耗尽和冷却先排除。Key 可采用最近 1h 实际 token 总量升序，窗口与并发占位待确认。
- “几乎总先用 5h”不是保证，不能覆盖耗尽、禁用或冷却限制。

无跨模型候选或额度读能力时停在研究结论，按用户要求不改 CPA；不得偷偷用模型请求次数冒充账户剩余额度。

## 10. 开发阶段与验收

A. 基线与契约（约 0.5–1 工程日）
- 固化现有 fallback/round-robin/random/weighted、冷却、身份检查与 streaming 行为。
- 确认手动身份重试、8 层深度、64 调用安全上限和请求级轮换语义。
- 产物：配置示例、错误码表、基线测试。

B. 手动成员级策略（约 1–2 日）
- schema／严格验证、manual_member、卡片选择和说明。
- 验收：选中叶子失败不切兄弟；身份检查保留；冷却直接报错；保存切换只影响新请求；stream/non-stream 一致。

C. 图验证与递归执行（约 3–5 日，最大风险）
- 分离组与叶子执行，共享预算和 stream commit；拒绝循环；不调用宿主 combo。
- 验收：A→B→C 子组内部先尝试完再返父层；共享 DAG 正确；层级预算不乘法放大；手动父组允许子组内部回退但不切父组兄弟。

D. 页面／诊断／能力验证（约 1–2 日）
- 树形预览、组选择、冷却解释、尝试路径与能力警告；无账号级伪标签。
- 验收：预览不改变下一次轮换；完整 ID 不折叠；密钥不进入日志；浏览器窄屏／长名称与截图检查。

E. CPA 实机兼容验收与发布（约 1–2 日）
- 先隔离 Docker 测试环境，用部署版 v8.0.16 和现有 SDK 固定版本验收，避免直接在 zgo 上开发。
- 覆盖 OpenAI Chat、Responses、Anthropic、Gemini 的流／非流；上游 mock 注入 429、5xx、4xx、换模及提交后断流。
- go test -race、go vet、配置迁移、旧配置结果对照、取消／资源关闭与并发压力测试。
- 发布前用户授权版本与生产部署；包含 registry、全部安装包与回滚说明。独立账号级功能不与第一阶段捆绑。

总计约 6.5–12 工程日，仅作为实现规模估算，不是完成日期承诺。

## 11. 风险和非目标

最高风险是递归失败分类、预算和已提交流；其次为旧配置归一化行为兼容。账号 Key 数量、内部重试与费用仍由 CPA 管理，插件预算不能宣称控制所有 HTTP 调用。

首版不做：CPA 源码修改、全账号统一排序、额度 API 请求、会话每轮识别、sticky 会话、首字超时、模式自动加入模型、最大上下文自动过滤。截图交互可参考，不复制未证实的能力。
